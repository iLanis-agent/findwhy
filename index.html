FindWhy

Why did find print that, and why didn't it print this?

Type a find expression. FindWhy shows how it is grouped, runs it on a small demo tree, and shows for every path which tests ran, what they returned, and where evaluation stopped.

Open the app

It explains the classic traps: -name a -o -name b -print printing only b, pruned directories showing up in the output, -o binding looser than the implicit -a, and the default -print that disappears once you write your own.

How it was tested

The engine ran 60,000 random expressions (6 seeds) against GNU find 4.8.0 on the same tree. 58,284 gave identical output, 1,569 were rejected by both. 147 differed, all in expressions that put -print or -prune among other tests: GNU find's optimizer reorders those, so real find departs from the documented left-to-right order. Of 35,582 expressions without them, 0 differed. A first seed was used while debugging. Entirely client-side; nothing leaves your browser.

Not covered: -exec, -delete, -ls, -size, -mtime, -perm, -regex, -depth, -L. Output is sorted; real find uses directory order.
